# Architecture Specification: Multi-Agent RAG Debugger

## 1. System Philosophy & Objectives
The **Multi-Agent RAG Debugger** transforms automated software debugging from speculative LLM text generation into an auditable, evidence-grounded engineering workflow. It is designed around four foundational principles:

1. **Evidence Grounding (RAG)**: An LLM must never speculate on codebase contents or generate fixes without concrete, source-attributed evidence retrieved from the actual codebase.
2. **Specialized Agent Separation**: Separate cognitive concerns into specialized agents: Issue Analysis, Root-Cause Diagnosis, and Fix Generation.
3. **Execution Guardrails**: Code generated by AI is untrusted. Patches must pass static security validation, be applied strictly to isolated temporary workspaces, and be evaluated against real test suites before review.
4. **Human-in-the-Loop Review**: No automated changes are published, committed, or deployed without explicit human approval.

## 3. Subsystem Breakdown

### 3.1 Issue Intake & Analysis Agent (`app/agents/issue_analyzer.py`)
- **Input**: User-submitted issue title, description, and repository path.
- **Cognitive Responsibility**: Categorize the defect (`bug`, `error`, `performance`, `security`, `test_failure`), determine severity priority (`low`, `medium`, `high`, `critical`), extract technical components, and synthesize targeted lexical and semantic search queries for retrieval.
- **Output**: Validated Pydantic `IssueAnalysis`.

### 3.2 Hybrid RAG Engine (`app/rag/`)
- **Scanning (`scanner.py`)**: Filters out virtual environments, binary files, `.git`, `node_modules`, and sensitive dotfiles (`.env`).
- **AST Parsing (`ast_parser.py`)**: Extracts Python class, function, async function declarations, and parameter lists, embedding symbol metadata directly into code chunks.
- **Chunking (`chunker.py`)**: Slices files into line-numbered windows while preserving start and end line ranges.
- **Embeddings & Vector Store (`embeddings.py`, `vector_store.py`)**: Computes dense vector representations with `sentence-transformers/all-MiniLM-L6-v2` and indexes them in a 384-dimensional FAISS index.
- **Hybrid Retrieval (`hybrid_retriever.py`, `keyword_retriever.py`, `evidence.py`)**: Fuses BM25 keyword matching with dense vector distance, ranking results through normalized score fusion.

### 3.3 Root-Cause Analysis Agent (`app/agents/root_cause.py`)
- **Input**: Issue report, structured analysis, and ranked code evidence.
- **Cognitive Responsibility**: Trace the defect through the actual code snippets, explain the causal chain, identify affected source files, and calculate a qualitative confidence score (0.0 to 1.0).
- **Rules**: Explicitly prohibited from fabricating files, symbols, line numbers, or speculative code outside the retrieved evidence.

### 3.4 Fix Generation Agent (`app/agents/fix.py`)
- **Input**: Diagnosis, issue description, and grounded evidence.
- **Cognitive Responsibility**: Synthesizes the minimal unified git diff patch required to resolve the problem.
- **Self-Healing / Retries**: If the initial patch response is malformed JSON or invalid diff syntax, prompts for correction with explicit validation errors.

### 3.5 Isolated Execution Sandbox (`app/tools/sandbox.py`, `app/tools/validator.py`)
- **Security Validation (`PatchSecurityValidator`)**: Analyzes target file paths in unified diff headers. Disallows path traversal (`../`), absolute paths, and sensitive files (`.env`, `.ssh`, `.exe`, `.sh`).
- **Disposable Workspace (`WorkspaceSandbox`)**: Copies the target repository into a temporary directory (`tempfile.mkdtemp()`). Applies the patch via `git apply` inside the isolated sandbox.
- **Test Runner (`TestRunner`)**: Executes the test suite in the isolated sandbox, captures exit codes and test breakdowns (run, passed, failed), and discards the workspace upon exit. The user's original repository is never modified.

### 3.6 LangGraph Workflow Controller (`app/core/graph_workflow.py`)
- State machine defined with `StateGraph(GraphWorkflowState)`:
  - `analyze` &rarr; `retrieve` &rarr; `root_cause` &rarr; `generate_fix` &rarr; `validate` &rarr; conditional edge (`retry` if tests fail and attempts < max, `complete` if passed, `failed` if exhausted).
- Tracks microsecond-precision telemetry traces (`StageTrace`) for each node.

### 3.7 Database Persistence Layer (`app/db/`)
- Managed by SQLAlchemy with support for both zero-config local **SQLite** and production **PostgreSQL + pgvector**.
- Stores complete debugging runs, issues, evidence snippets, patches, test outputs, execution duration, and human approval records.
